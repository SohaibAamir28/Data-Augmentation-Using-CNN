Slide 2 · IntroductionSohaib
EnglishThis topic came from Lecture 7, on the similarity and affine slides, where Sir said: “Toh jo image hai na, uski na ye saari augmentation hai.” Every transformation we wrote as a 3×3 matrix is also a way to create a new, correctly-labelled training image: a cat rotated by 10 degrees is still a cat. Data augmentation means creating new training images by transforming existing ones while keeping the label. There are two kinds. Geometric augmentation changes position, size and viewpoint, so it needs warping and interpolation. Photometric augmentation changes brightness, contrast, saturation and noise, pixel by pixel, with no warping. Our task was to explain the maths, implement both on a CNN, and prove the gain with numbers.
Roman UrduYe topic Lecture 7 se aaya, similarity aur affine wali slides par, jab Sir ne kaha: “Toh jo image hai na, uski na ye saari augmentation hai.” Har transformation jo humne 3×3 matrix se likhi, wo ek nayi training image banane ka tareeqa bhi hai jiska label sahi rehta hai: 10 degree ghoomi hui billi phir bhi billi hai. Data augmentation ka matlab: maujooda images ko transform kar ke nayi images banana, label same. Do qisam: geometric (position, size, viewpoint) jis mein warping aur interpolation chahiye; aur photometric (brightness, contrast, saturation, noise) jo har pixel par alag lagti hai, warping nahi. Hamara kaam: maths samjhana, dono ko CNN par lagana, aur numbers se saabit karna.
Slide 3 · Problem statementSohaib
EnglishTwo problems motivate this work. First, overfitting with limited data: our CNN has 6.5 million parameters and can memorise 10,000 images, reaching 100% training accuracy, but only 78.5% on images it has not seen, a 21.5-point gap. Second, fragile inference: real test images are rotated, shifted, darker or noisier. Without augmentation, accuracy drops by 51% on rotated and dark images. Our goal is to use the Lecture 7 transformations as augmentation and measure, on a fixed held-out test set, how much accuracy and robustness improve. Both numbers come from our own baseline run.
Roman UrduDo masle hain. Pehla, kam data par overfitting: hamare CNN mein 6.5 million parameters hain, wo 10,000 images ka ratta laga leta hai, training accuracy 100%, lekin nayi images par sirf 78.5%: 21.5 points ka gap. Doosra, kamzor inference: asal test images ghoomi hui, khiski hui, andheri ya noisy hoti hain. Augmentation ke baghair ghoomi aur andheri images par accuracy 51% gir jati hai. Hamara maqsad: Lecture 7 ki transformations ko augmentation bana kar fixed test set par naapna ke accuracy aur robustness kitni barhti hai. Ye dono numbers hamare apne baseline run se hain.

Slide 5 · Transformation hierarchySohaib
EnglishEach step adds freedom, and each step gives a new augmentation. Translation has 2 degrees of freedom and gives random shifts. Euclidean, or rigid, adds rotation: 3 DoF. Similarity adds uniform scale, so zoom: 4 DoF. Affine has six free parameters a to f, adding shear, aspect change and flip. Homography has 8 DoF and simulates a change of viewpoint. This also answers the question from class about how many points we need. Each point pair gives two equations, so the minimum is the DoF divided by two, rounded up. Rigid has 3 DoF, and one pair gives only 2 equations, so we need 2 pairs. A homography has 9 entries but is defined up to scale, so we fix the last one to 1 and get 8 unknowns: 4 pairs.
Roman UrduHar qadam par azadi barhti hai aur ek nayi augmentation milti hai. Translation: 2 DoF, random shift. Euclidean (rigid): rotation add, 3 DoF. Similarity: uniform scale yani zoom, 4 DoF. Affine: chhe parameters a se f, shear, aspect aur flip. Homography: 8 DoF, viewpoint change. Class wale sawal ka jawab bhi yehi hai ke kitne points chahiye: har point pair 2 equations deta hai, to minimum = DoF ÷ 2, upar round. Rigid ke 3 DoF hain, ek pair sirf 2 equations deta hai, isliye 2 pairs. Homography ke 9 entries hain lekin wo scale tak defined hai, last entry 1 fix: 8 unknowns, 4 pairs.
Slide 6 · Transformations in actionSohaib
EnglishThese images come from our own NumPy code, written from scratch. Rigid and similarity transforms keep angles; only position, orientation and size change. Affine keeps parallel lines parallel, so a square becomes a parallelogram. Homography keeps only straight lines, so a square can become any quadrilateral. Every panel uses inverse warping with bilinear interpolation. The black regions are pixels whose source falls outside the image.
Roman UrduYe images hamare apne NumPy code se hain, scratch se likha. Rigid aur similarity angles ko same rakhte hain, sirf position, rukh aur size badalta hai. Affine mein parallel lines parallel rehti hain, square parallelogram ban jata hai. Homography mein sirf seedhi lines seedhi rehti hain, square koi bhi chaar-kona shape ban sakta hai. Har panel inverse warping aur bilinear interpolation se bana. Black hissay woh pixels hain jinka source image ke bahar hai.
Slide 7 · Solving from point pairsSohaib
EnglishThree point pairs fix an affine transform and four fix a homography. For affine, we stack two rows per pair into a 6×6 system and solve it by least squares; the error on the targets is 2×10⁻¹³ pixels. For homography we use the DLT: an 8×9 system A·h = 0. The solution is the singular vector of A with the smallest singular value, and we divide by the last entry. The error is 3×10⁻¹⁰ pixels. With the minimum number of pairs the fit is exact; the error is only floating-point rounding. With more pairs, least squares averages the noise, and that leads to RANSAC.
Roman UrduTeen point pairs affine ko fix karte hain, chaar homography ko. Affine: har pair se 2 rows, 6×6 system, least squares se solve; error 2×10⁻¹³ pixel. Homography: DLT, 8×9 system A·h = 0; jawab A ka woh singular vector jiski singular value sab se chhoti hai, phir last entry se divide; error 3×10⁻¹⁰ pixel. Minimum pairs par fit exact hai, error sirf rounding ka. Zyada pairs hon to least squares noise average karta hai, aur aage RANSAC aata hai.
Slide 8 · HomographySohaib
EnglishA homography simulates a new camera viewpoint. In homogeneous coordinates, x′ equals (ax + by + c) divided by (gx + hy + 1). The terms g and h make the divisor change across the image, so parallel lines can meet: that is perspective. Two images taken from the same centre of projection are related by a homography; this is where the lecture was heading. As augmentation, a small random H shows the same object from a slightly different angle. We keep g and h within ±0.0008 per pixel on 32×32 images. Homographies are also used for panoramas and in SuperPoint's homographic adaptation.
Roman UrduHomography naya camera viewpoint simulate karti hai. x′ = (ax + by + c) ÷ (gx + hy + 1). g aur h ki wajah se denominator image mein jagah jagah badalta hai, to parallel lines mil sakti hain: yehi perspective hai. Same center of projection se li gayi do images ka rishta homography hai; lecture yahin ja raha tha. Augmentation mein chhoti random H = wahi object thore alag angle se. Hum 32×32 images par g, h ko ±0.0008 per pixel rakhte hain. Homography panorama aur SuperPoint ki homographic adaptation mein bhi use hoti hai.
Slide 9 · Section: Mathematical mechanicsSohaib
EnglishNow the mechanics: how a matrix actually produces a new image, through forward or inverse warping and interpolation.
Roman UrduAb mechanics: matrix se asal nayi image kaise banti hai: forward ya inverse warping, aur interpolation.
Slide 10 · Forward vs inverse warpingSohaib
EnglishIn forward warping we push each source pixel to its target, x′ = H·x. With a zoom of 1.35 and a 20-degree rotation, 45% of the target pixels receive nothing: holes. Zooming in creates more target pixels than source pixels, so pushing can never fill them all. In inverse warping we pull: every target pixel asks where it came from, x = H⁻¹·x′, and interpolates there. Each target is visited exactly once, so there are no holes. Every augmentation library uses inverse warping, and so do we.
Roman UrduForward warping mein har source pixel ko target ki taraf “push” karte hain: x′ = H·x. 1.35 zoom aur 20 degree rotation par 45% target pixels ko kuch nahi milta: holes. Zoom-in mein target pixels source se zyada hote hain, push se sab nahi bharte. Inverse warping mein “pull” karte hain: har target pixel poochta hai ke wo kahan se aaya, x = H⁻¹·x′, aur wahan interpolate karta hai. Har target ek baar visit hota hai, koi hole nahi. Har augmentation library yehi use karti hai, aur hum bhi.
Slide 11 · Interpolation methodsSohaib
EnglishInverse warping lands between pixels, so we interpolate. Nearest neighbour copies the closest pixel. It is fastest, but edges turn blocky. Bilinear uses 4 pixels: linear in x, then in y. This is the Q11, Q12, Q21, Q22 derivation from the lecture. It is smooth and slightly soft, and it is the default in most libraries. Bicubic uses 16 pixels: a cubic through 4 points in each of 4 rows, then one more cubic across. We use the Keys kernel with a = −0.5. It gives the sharpest edges but can overshoot. All three are written from scratch in geometry.py.
Roman UrduInverse warping do pixels ke beech girta hai, isliye interpolation. Nearest neighbour sab se qareeb pixel copy karta hai: sab se tez, lekin edges blocky. Bilinear 4 pixels: pehle x mein linear, phir y mein; lecture ka Q11, Q12, Q21, Q22 derivation. Smooth, thora soft, zyada tar libraries ka default. Bicubic 16 pixels: 4 rows mein har ek par cubic, phir ek aur cubic across; Keys kernel a = −0.5. Sab se sharp lekin overshoot ho sakta hai. Teeno geometry.py mein scratch se likhe.

At augmentation scale, with small warps of 32×32 images, the difference is much smaller. We test whether it changes accuracy in the ablation later. Now Abdul Rafeh will explain our method.

Slide 14 · Geometric augmentation pipelineAbdul Rafeh
EnglishFor every image in every epoch we build one random 3×3 matrix: H = C·P·T·R·Sh·S·F·C⁻¹. F is a horizontal flip with probability one half. S is a scale between 0.85 and 1.15, Sh a shear of up to 10 degrees, R a rotation of up to 15 degrees, T a translation of up to 4 pixels, and P a small perspective term. Each one is a transformation from the lecture. C moves the origin to the image centre: to rotate about the centre we translate, rotate and translate back. We multiply everything into one homography and apply it by inverse warping with grid_sample interpolation, on the GPU.
Roman UrduHar epoch mein har image ke liye ek random 3×3 matrix: H = C·P·T·R·Sh·S·F·C⁻¹. F: horizontal flip, probability aadha. S: scale 0.85 se 1.15. Sh: shear 10 degree tak. R: rotation 15 degree tak. T: translation 4 pixel tak. P: chhota perspective. Har ek lecture ki transformation hai. C origin ko image ke center par le jata hai: center ke gird ghumane ke liye translate, rotate, wapis translate. Sab ko multiply kar ke ek homography, phir GPU par inverse warping aur grid_sample interpolation.
Slide 15 · Photometric augmentationAbdul Rafeh
EnglishPhotometric augmentation changes pixel values, not positions. Brightness multiplies the image by beta. Contrast scales the image around its mean gray. Saturation scales it around its grayscale version. We add sensor noise with sigma up to 0.04, and 10% of images are made grayscale. Geometric augmentation answers: where is the object, how big is it, and from which angle? Photometric answers: what lighting, which camera, how much noise? Neither changes the label.
Roman UrduPhotometric pixel ki value badalta hai, position nahi. Brightness: image ko beta se multiply. Contrast: mean gray ke gird scale. Saturation: grayscale version ke gird scale. Sensor noise sigma 0.04 tak, aur 10% images grayscale. Geometric jawab deta hai: object kahan hai, kitna bara, kis angle se? Photometric: kaisi roshni, kaun sa camera, kitna noise? Dono label nahi badalte.

Roman UrduYe CIFAR-10 par hamari GPU pipeline ka asli output hai. Har epoch naye random parameters, to 60 epochs = har image ke 60 alag versions. Slide 25 · Modern augmentation methodsMahmoob
EnglishWe compare 9 methods. The standard baseline is random crop plus flip. AutoAugment learns a policy with reinforcement learning. RandAugment removes the search: 2 random operations at one magnitude. TrivialAugment applies one random operation at a random strength, with no parameters at all. AugMix mixes augmentation chains and adds a Jensen–Shannon consistency loss for robustness. Mixup blends two images, and CutMix pastes a patch, with the labels mixed in proportion. Finally, a combined modern recipe. Every method shares one model, optimiser, schedule and data split; only the augmentation changes. The policy methods use torchvision's reference implementations.
Roman Urdu9 methods. Standard baseline: random crop + flip. AutoAugment: reinforcement learning se policy seekhta hai. RandAugment: search khatam, 2 random operations ek magnitude par. TrivialAugment: ek random operation random strength par, koi parameter nahi. AugMix: augmentation chains mix karta hai aur robustness ke liye Jensen–Shannon consistency loss. Mixup: do images blend; CutMix: patch paste; labels ratio se mix. Aur ek combined modern recipe. Sab ka model, optimizer, schedule aur data same; sirf augmentation alag. Policy methods torchvision ki reference implementations hain.

Part C · 10 questions Sir is most likely to ask

The full bank of 50 questions is in the Roman Urdu project-explanation PDF.

1. How many point pairs for a rigid transform, and why?
EN: Two. It has 3 DoF and each pair gives 2 equations; one pair gives only 2, so we need 2 pairs.
UR: Do. 3 DoF hain, har pair 2 equations deta hai; ek pair kaafi nahi, isliye 2.
2. Why 8 DoF for a homography, not 9?
EN: It is defined up to scale: H and kH give the same mapping after dividing by w, so we fix h₃₃ = 1.
UR: Scale tak defined hai: H aur kH same mapping; isliye h₃₃ = 1 fix.
3. Why inverse warping instead of forward?
EN: Forward warping leaves holes (45.1% in our demo); inverse warping visits every target pixel once, with no holes.
UR: Forward mein holes (hamare demo mein 45.1%); inverse har target pixel ek baar visit karta hai, koi hole nahi.
4. Derive bilinear interpolation.
EN: Interpolate in x: R1 = (1−dx)Q11 + dx·Q21 and R2 = (1−dx)Q12 + dx·Q22. Then in y: f = (1−dy)R1 + dy·R2.
UR: Pehle x mein R1, R2; phir y mein f = (1−dy)R1 + dy·R2.
5. How is a homography solved from 4 pairs?
EN: By the DLT: 8 linear equations, A·h = 0. Take the SVD; h is the right singular vector with the smallest singular value, then divide by h₃₃.
UR: DLT: A·h = 0, SVD, sab se chhoti singular value wala vector, phir h₃₃ se divide.
6. How do you prove reduced overfitting?
EN: The train–test gap falls from 21.5 to 13.2 points, validation loss falls by 34%, and test accuracy rises by 6.9 points. This holds over 3 seeds, and the test set was never used in training.
UR: Gap 21.5 se 13.2, validation loss 34% kam, test +6.9; 3 seeds; test set training mein kabhi nahi.
7. Isn't testing on shifts you trained on cheating?
EN: Partly, which is why we also report blur (never trained on: +29 points) and the independent CIFAR-10-C benchmark, where we rank 2nd of 9.
UR: Kuch had tak; isliye blur (kabhi train nahi: +29) aur CIFAR-10-C (2nd of 9) bhi report kiye.
8. Does the interpolation method matter for the CNN?
EN: Only a little: 85.3% to 86.4%, a 1.1-point spread from one seed, which is much smaller than the 6.9-point gain from augmentation itself.
UR: Thora sa: 85.3–86.4, 1.1 points; augmentation ke 6.9 points se kahin kam.
9. Is your project state of the art?
EN: We benchmarked against 8 modern methods. We are 2nd of 9 on CIFAR-10-C robustness (86.0% against AugMix's 87.0%) but about 1.5 points lower on clean accuracy. Part of our noise robustness comes from training with noise.
UR: 8 modern methods se compare kiya: robustness mein 2nd (86.0 vs AugMix 87.0), clean accuracy ~1.5 kam; noise par faida kuch had tak noise training se.
10. When can augmentation hurt?
EN: When it changes the label (6 ↔ 9, flipped text) or is so strong that the object is no longer recognisable.
UR: Jab label badal de (6 ↔ 9, ulta text) ya itni strong ho ke object pehchan mein na aaye.
